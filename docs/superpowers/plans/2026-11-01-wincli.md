# wincli（Windows 正式客户端）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Windows POC 验证过的能力正式化：Windows 上获得与 macOS 对等的客户端（daemon 数据面、Windows 服务、CLI 全命令、DNS NRPT、线上/离线安装）。

**Architecture:** 方案一——POC（crates/poc4）验证过的代码按 `cfg(windows)` 分叉回迁正式 crate（zt-core/daemon/cli），mac/linux 代码路径零行为改动；IPC 复用既有 loopback TCP；安装链新增 install.ps1 与 zip 产物。

**Tech Stack:** Rust 2021、tun-rs（wintun L3）、route_manager（Windows 后端）、windows-sys（SCM/互斥体）、PowerShell（NRPT/安装脚本）、cargo-xwin（交叉构建）。

## Global Constraints

- **cfg 隔离红线**：全部 Windows 代码以 `#[cfg(windows)]` / `#[cfg(target_os = "windows")]` 分叉；mac/linux 既有代码路径**零行为改动**（纯文件移动允许，逻辑改动禁止）。每个任务收尾必验：`cargo build --workspace` 与 `cargo build --workspace --release`（mac 本机）双绿。
- **交叉编译门**：涉及 zt-core/daemon/cli 的任务，收尾加验 `cargo xwin check --target x86_64-pc-windows-msvc -p <本任务 crate>`（xwin 环境见 Task 1 说明）；zt-core 三个回迁任务全部完成后的里程碑验证：`cargo xwin check --target x86_64-pc-windows-msvc --workspace`（poc4 除外已绿）。
- **不添加测试用例**（用户全局规则）：验证 = 构建 + 静态审查 + Task 11 实机 e2e。
- **回迁来源以 poc4 为准**：POC 代码已实机验证（报告 docs/2026-10-31-windows-poc-report.md）；回迁时照抄语义、适配接口，不重新发明。
- **目录/命名（全局唯一真值）**：程序目录 `C:\Program Files\planet-port\`；数据目录 `C:\ProgramData\planet-port\`（registry.json、planets/、port、authtoken.secret、per-planet 数据）；服务名 `planetportd`（显示名 `Planet Port Daemon`）；适配器名前缀 `planet-port`（POC 既有）；产物 `planet-port_<ver>_windows_x86_64.zip` 内含 `planet-port.exe`、`planet-portd.exe`、`wintun.dll`、`install-offline.ps1`。
- **wintun.dll**：版本 0.14.1，SHA256 `e5da8447dc2c320edc0fc52fa01885c103de8c118481f683643cacc3220dafce`，vendor 入库 `third_party/wintun/wintun.dll`，exe 同目录摆放。
- **不做代码签名**；文档注明 SmartScreen 拦截属预期。
- **提交规范**：Conventional Commits 中文 description+Body，禁 Co-authored-by；全部工作在 `windows-poc` 分支。
- **绑定形态实证（POC 已验证，回迁直接用）**：`AF_INET:u32`、`in6_addr.u.Byte`、`sin_family:ADDRESS_FAMILY`、`in_addr.S_un.S_addr`、netconfRevision 与 multicastSubscribe ADI 为 `c_ulong`（32 位）。
- **回调红线（node.rs 既有架构约束，Windows 分叉同样遵守）**：回调 glue 只做拷贝+channel send；全部 sink 调用在驱动线程内 catch_unwind 包裹；关停硬顺序 running=false → 唤醒 → Cmd::Stop → join → ZT_Node_delete → drop Inner。

**Interfaces:**
- Consumes: 既有 `NodeHandle/NodeParams/NodeSink/Cmd`（node.rs 内既有定义，**签名一字不改**——daemon 侧零改动）
- Produces: `NodeHandle` 在 Windows 上语义等价可用（后续 Task 3 的 device_win、Task 5 的 daemon 直接消费）

**回迁要点（对照 poc4/src/driver.rs 与 zt-core/src/node.rs 逐处落地）**：

1. **唤醒机制**：`Inner.wake_wr: File`（pipe 写端）→ Windows 用 `Sender<u8>`（mpsc）；`Inner::wake()` 由 `libc::write(pipe)` 改为 `wake_tx.send(1)`。`Driver.wake_rd: File` → `Receiver<u8>`。
2. **`make_pipe()`**（node.rs:220）整函数 `#[cfg(not(windows))]`；Windows 分支直接 `channel::<u8>()`。
3. **UDP 非阻塞模型反转**：Unix 是"非阻塞 socket + poll"；Windows 照 poc4——**阻塞 socket + `set_read_timeout(50ms)` + 独立读线程**：
   - `NodeHandle::start` 内 `udp.set_nonblocking(true)` 仅非 Windows；Windows 设 `udp.set_read_timeout(Duration::from_millis(50))` 并 `spawn(run_udp_reader(...))`（读线程：`recv_from` → `udp_tx` 通道 → 发 `wake_tx`；循环条件 `running.load()`；读错误按 poc4 driver.rs 的 WSAECONNRESET 处理——driver.rs:496 注释的 ICMP port-unreachable 语义）。
   - 驱动线程主循环（node.rs:674-733 的 poll 段）Windows 分叉为：`cmd_rx.try_recv()` + `wake_rx.recv_timeout(clamp(1,500ms))` + `udp_rx.try_recv()` 排空（poc4 已验证节奏）。
4. **`udp_fd`**：`as_raw_fd()` → Windows `as_raw_socket()`（`std::os::windows::io::AsRawSocket`），`processWirePacket` 的第 4 参 `i64::from(fd)` 照 poc4。
5. **`multicastSubscribe` ADI**：node.rs:668 既有 `u32::from(*ip) as libc::c_ulong` 在 Windows 上 libc::c_ulong=u32，类型天然成立，不改；仅确认编译。
6. **POC 裁剪项回补**：poc4 的 Cmd 只有 Join/Stop；回迁后沿用 zt-core 既有 `Cmd::{Join,Leave,Orbit,Deorbit,Stop}` 全集（Windows 驱动循环同样 try_recv 处理），pathCheck/pathLookup 维持 zt-core 现状（若现为 None 保持 None，不新增）。
7. **sa.rs**：Windows 分支照 poc4/src/sa.rs（bindgen MSVC 布局：`a.sin_port` 同构、`in6_addr.u.Byte`、`ADDRESS_FAMILY`）合入现有 `cfg(target_os = "macos")` 旁。
8. **ifaddr.rs**：`libc::getifaddrs` 是 Unix-only。Windows 分支用 `getifaddrs` crate（crates.io `getifaddrs = "0.2"`，MIT，跨平台同 API）；`[target.'cfg(windows)'.dependencies]` 声明。函数签名 `pub fn local_ipv4s() -> Vec<Ipv4Addr>` 不变。
9. **Cargo.toml**：`libc` 移到 `[target.'cfg(not(windows))'.dependencies]` 若 Windows 全程不用 libc（检查 state.rs 的 `chmod 0o600` 若用 unix PermissionsExt 需 `cfg(unix)` 门——权限收敛 Windows 侧由数据目录 ACL 承担，代码层跳过并注释）。

### Task 6: daemon SCM 服务入口

**Files:**
- Create: `crates/daemon/src/service_win.rs`（SCM 胶合层）
- Modify: `crates/daemon/src/main.rs`（入口分叉：服务上下文 vs 控制台）
- Modify: `crates/daemon/Cargo.toml`（windows-sys features 补 `Win32_System_Services`）

**Interfaces:**
- Consumes: Task 5 的 `shutdown_signal()` 抽象
- Produces: `planet-portd.exe --service` 以 Windows 服务方式运行（Task 7 的 sc create 消费此入口）；SCM STOP 控制码 → 触发既有优雅收尾（registry 落盘/拆设备）

**设计（手写 SCM，不引 service 框架）**：

```rust
//! crates/daemon/src/service_win.rs —— Windows 服务胶合层(SCM 手写,零第三方依赖)
//!
//! 服务身份运行(main 检测 --service 参数):注册 SERVICE_CONTROL_HANDLER →
//! 报 RUNNING → 在工作线程跑既有 daemon 主逻辑(tokio runtime 原样)→
//! STOP/SHUTDOWN 控制码置停止信号 → 等主逻辑收尾后报 STOPPED 退出。
//! 控制台直跑(无 --service)不经过本模块,行为与 mac/linux 一致。

use windows_sys::Win32::Foundation::{ERROR_CALL_NOT_IMPLEMENTED, NO_ERROR};
use windows_sys::Win32::System::Services::*;

static STOP_TX: std::sync::OnceLock<std::sync::mpsc::Sender<()>> = std::sync::OnceLock::new();

unsafe extern "system" fn handler_ctrl(dw_control: u32) {
    if matches!(dw_control, SERVICE_CONTROL_STOP | SERVICE_CONTROL_SHUTDOWN) {
        if let Some(tx) = STOP_TX.get() {
            let _ = tx.send(());
        }
    }
}

/// 服务主函数:由 main 在 --service 时调用;阻塞直至停止。
pub fn run_service<F: FnOnce() + Send + 'static>(main_body: F) -> u32 {
    let mut table = [SERVICE_TABLE_ENTRY {
        lpServiceName: w!("planetportd"),
        lpServiceProc: Some(service_proc),
    },
    SERVICE_TABLE_ENTRY { lpServiceName: std::ptr::null(), lpServiceProc: None }];
    unsafe {
        if !StartServiceCtrlDispatcherW(table.as_mut_ptr()).as_bool() {
            return unsafe { GetLastError() };
        }
    }
    0
}

unsafe extern "system" fn service_proc(_argc: u32, _argv: *mut *mut u16) {
    // 注册控制处理器并报 START_PENDING → 主逻辑线程 → RUNNING → 等 STOP
    let status_handle = unsafe { RegisterServiceCtrlHandlerExW(w!("planetportd"), Some(handler_ctrl), std::ptr::null()) };
    let (tx, rx) = std::sync::mpsc::channel::<()>();
    let _ = STOP_TX.set(tx);
    let h = status_handle;
    let report = |state: u32, exit: u32| unsafe {
        let mut s = SERVICE_STATUS {
            dwServiceType: SERVICE_WIN32_OWN_PROCESS,
            dwCurrentState: state, dwControlsAccepted: SERVICE_ACCEPT_STOP | SERVICE_ACCEPT_SHUTDOWN,
            dwWin32ExitCode: exit, dwServiceSpecificExitCode: 0,
            dwCheckPoint: 0, dwWaitHint: 30000,
        };
        SetServiceStatus(h, &s);
    };
    report(SERVICE_START_PENDING, 0);
    let worker = std::thread::spawn(main_body);   // main_body 内含 daemon 完整主逻辑
    report(SERVICE_RUNNING, 0);
    let _ = rx.recv();                            // STOP 到达
    report(SERVICE_STOP_PENDING, 0);
    let _ = worker.join();                        // 优雅收尾在 main_body 内完成(等待 shutdown_signal 路径)
    report(SERVICE_STOPPED, 0);
}
```

**main.rs 分叉**：

```rust
// 参数解析后、单例检查前:

    return service_win::run_service(|| daemon_main(args));   // daemon_main = 既有 main 主体重构出的闭包/函数
}
```

既有 main 主体抽成 `daemon_main(args)`（纯重构，mac/linux 复用）；`shutdown_signal()` 的 Windows 实现接到 `STOP_TX` 的接收端（`rx.recv()` 包成 async 或用 `tokio::task::spawn_blocking` + Notify）。

**硬性要求**：worker.join() 不设超时但有界——daemon_main 的收尾本身有界（既有 shutdown 设计），join 前报 STOP_PENDING 的 WaitHint 30s 内完成。
